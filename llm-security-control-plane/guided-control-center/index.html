    bundle의 logs는 결정 기록, spans는 처리 단계, closures는 처리가 끝났다는 기록, downstream_calls는 실제 저장소 호출 목록입니다. 모두 request_id·trace_id로 연결합니다.

    각 collection은 사전의 목록입니다. 대상 요청에는 결정 Log와 closure가 각각 정확히 한 건 있어야 합니다. Log는 decision·stop_stage, Span은 stage·정수 sequence, closure는 closed·downstream_count를 같은 level의 key로 가집니다. downstream_calls는 실제 호출 한 건당 한 사전이며 대상 request_id의 행 수를 셉니다. stages 반환값은 sequence 순서의 stage 문자열 목록입니다.

    LEARNER-OWNED MCP SERVER
    
              
    Tool 제안과 실행 권한 분리하기
    
              
    ~/owasp-llm-practice/P07-02_server.py는 공식 SDK의 Streamable HTTP Server입니다. Starter는 요청마다 임의 nonce를 새로 만들어 승인 없는 호출도 실행합니다. verify_approval()의 자기 승인 거부 조건을 채우고, publish_notice()의 제공된 try/except·transaction은 유지하면서 검증 호출과 서명된 nonce를 연결합니다.
    
              
    서명된 승인과 실제 요청의 주체·Tool·인자·실행 및 Trace를 대조하고 만료 여부를 확인하세요. 승인 없이 호출하거나 다른 인자로 바꾸면 공지가 생성되면 안 됩니다. 정확한 승인 한 번만 실행되고 같은 승인은 다시 사용할 수 없어야 합니다.
    
              
    검사 뒤 SQLite transaction이 nonce 소비와 훈련 공지 기록을 함께 처리합니다. 그래서 다른 인자, 만료 Token과 같은 nonce 재사용은 공지를 만들기 전에 멈춥니다. Host의 승인과 실제 공지는 같은 trace_id에 묶입니다.
